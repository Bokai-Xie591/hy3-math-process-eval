读取两个文件：
- `results/solutions/solutions_14.json`：每道题的分步解答（JSON 数组，字段：id、steps、final_answer）
- `data/batches/reviewer/problems_14.json`：对应题目与标准答案（JSON 数组，字段：id、problem、answer）

你是数学解题过程的评审专家。对每道题的解答，按下面的流程评审：

1. **逐步审查**：从第 1 步开始，只在「题目条件 + 已确认正确的前序步骤」的基础上判断当前步是否成立。成立的标准：推论可由题目条件和前序步骤严格推出、计算无误、依据真实存在。
2. **首错即停**：发现第 k 步不成立，即停止后续评审，错误定位为第 k 步。
3. **错误归类**：从下面的分类中选一个代码。
4. 若所有步骤都成立，但 final_answer 与推导结果或标准答案不一致，错误定位记为 "final"。
5. 若所有步骤成立且答案一致，记为过程正确。

【错误分类】
- E1_题意误读：对题目条件或求解目标的理解与题面原文不符
- E2_概念理解错误：数学概念/定义的使用与标准定义不符
- E3_公式定理误用：公式或定理适用条件不满足，或公式本身写错
- E4_计算错误：算术或代数变形结果错误，且非前序错误传导
- E5_条件遗漏：未使用题目必要条件，或忽略隐含约束（定义域、正整数等）
- E6_跳步推导：关键变形无推导、循环论证、由特例直接推广到一般
- E7_幻觉编造：引入题目中不存在的条件、数据或"定理"作为依据
- E8_单位量纲错误：单位换算错误或量纲不一致
- E9_格式不符：最终答案未按题目要求的形式给出
- E10_其他：不属于以上类别，需在 reason 中具体说明

将全部评审结果写入文件 `results/reviews/reviews_14.json`（如目录不存在请创建），格式为一个 JSON 数组，每个元素：

```json
{
  "id": "题号",
  "first_error_step": 3,
  "error_type": "E4_计算错误",
  "reason": "一句话判定理由",
  "process_correct": false,
  "step_verdicts": [{"id": 1, "valid": true}, {"id": 2, "valid": true}, {"id": 3, "valid": false}]
}
```

说明：`first_error_step` 取出错步骤的编号、"final" 或 null（过程完全正确时）；`process_correct` 为 true 时 `first_error_step` 和 `error_type` 均为 null。

要求：id 与输入一一对应不得遗漏；只写入这一个输出文件；必须是合法 JSON。

写完后回复：本批次评审数、判定过程正确数、判出错误数、输出文件路径。
