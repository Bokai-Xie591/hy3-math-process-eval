# Demo 视频脚本（≤ 2 分钟）

> 目标：展示一次完整的"解题 → 过程评估 → 错误定位"流程。
> 最有说服力的演示不是"模型做对了"，而是"评估器抓住了错误"——所以演示用金标样本。

## 分镜

**0:00–0:15 开场（口播 + 标题页）**
- 画面：项目名 + 一句话定位："基于混元 Hy3 的数学解题过程评估与错误定位系统"
- 口播：只看最终答案会漏掉过程错误，这个系统做逐步质检、定位出错步骤、归类错误类型

**0:15–0:45 环节一：解题（WorkBuddy + Hy3）**
- 操作：打开 WorkBuddy，模型选 Hy3，发送解题批次指令
- 画面重点：Hy3 分步解答写入 `solutions.json` 的过程
- 口播：305 道分层题（基础到竞赛、压轴），Hy3 产出结构化分步解答，全部答对

**0:45–1:30 环节二：过程评审抓错（核心演示）**
- 操作：发送评审指令，评审一条**删除了中间步骤的解答**
  （gold2-008：斐波那契型递推，删掉"a₅=445"这一步，最终答案仍是 1336 完全正确）
- 画面重点：评审输出 JSON 中 `first_error_step: 5`、`error_type: E6_跳步推导`、
  `reason`："a₅=445 从未在前序步骤中计算"
- 口播：这是最难抓的一类错误——答案完全正确、过程缺环。评审器发现第 5 步引用了
  从未推导的 a₅=445，精确定位到缺环位置。实质性跳步检出率 100%、定位 100% 准确；
  值篡改与依据编造类错误也是 30 条全检出、全定位

**1:30–2:00 环节三：结果总览**
- 画面：终端跑 `merge_results.py` 和 `analyze_upgrades.py` 输出统计表 + 五张图表
  （分层表现 / 步数分布 / 金标验证 / E6 判定边界 / 边界三重稳定性）
- 口播：正常集 305 题 + 外部经典题 20 题全部正确、零误报；值篡改类金标 30 条全检出、
  全定位；删步实验 30 条揭示评审器的判定边界——"幻影引用"型跳步 12 条全抓，
  可一步核验的压缩按评分惯例容忍；该边界换提示词、换评审协议、换模型家族
  （GLM-5.2 复核 60 条逐样本一致）都稳定不变

## 录制提示

- 用屏幕录制（如 Windows 自带 Xbox Game Bar：Win+G）录 WorkBuddy 操作 + 终端
- 解题和评审各录一次完整过程即可，等待时间可剪辑加速
- gold2-008 的解答在 `results/gold2/solutions_gold2.json`，评审指令用
  `prompts/gen/review_gold2_v2.txt`（v1/v2 对该样本判定一致）
- 结尾 3 秒停留：GitHub 仓库链接
