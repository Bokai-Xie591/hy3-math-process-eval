# 过程评估方法说明（评估设计文档 · 初稿）

## 1. 评估目标

不只判断最终答案对错，还要回答三个问题：

1. 推理过程是否成立（有无跳步、循环论证、误用定理、条件遗漏、幻觉）；
2. 出错时，错误从哪一步开始；
3. 错误属于什么类型（见错误分类体系）。

并重点识别一类隐蔽样本：**最终答案正确，但推理过程无法支撑该结论**
（猜中答案、数值巧合、误用定理却得对结果）。

## 2. 评估流程

```
题目 + 标准答案
   │
   ├─ 解题 pipeline（Hy3）→ 分步解答 steps + final_answer
   │
   ├─ 答案校验（规则层）── 精确匹配 / 数值等价 / 符号等价(sympy)
   │
   └─ 过程评估器（LLM 评审层）
        逐步审查：第 i 步仅在 1..i-1 步全部确认正确后评审
        ├─ 全部成立 & 答案正确  → 过程正确
        ├─ 全部成立 & 答案错误  → 错误定位于 final（答案与推导不一致）
        └─ 第 k 步不成立        → 错误定位于第 k 步，按分类体系归类，停止后续评审
```

设计依据：

- **逐步评审**优于一次性整篇评审：整篇评审容易遗漏中间步骤的细微错误，
  且无法给出稳定的"首个出错步"定位；逐步评审把每次判断的上下文缩小到
  "题目 + 已确认正确的前序步骤 + 当前步"，判定标准更易操作、结论更可复现。
- **首个错误即停**：后续步骤的错误多由首错传导，计入会污染错误类型分布。
- 评审温度固定为 0，减少评审结果波动（一致性验证用）。

## 3. 错误分类体系

见 `src/process_eval/taxonomy.py`，共 10 类（E1 题意误读 … E10 其他），
每类给出可操作的判定标准，避免"基本符合"式模糊表述。

## 4. 有效性验证计划（对应任务要求的两项）

1. **定位准确率**：构建带金标的验证集——取正确解答，用脚本在第 k 步注入
   已知错误（如篡改中间计算结果、替换错误公式），gold_error_step = k；
   检验评估器能否定位到第 k 步。
2. **误报率**：在答案正确的样本上，统计被判过程有问题的比例；再由人工
   抽检这些样本，区分"真实过程问题"与"评审误报"。

## 5. 结果分析计划

- 最终答案准确率 / 过程正确率 / 错误类型分布；
- 按难度（L1 基础 / L2 中等 / L3 较难）分层，定位模型表现明显下降的区间；
- 典型 case 归因分析（每类错误挑 1~2 个代表样本）。
